## 数据位置

应用首次启动时在 macOS 应用数据目录创建 `wealth-manager.sqlite3`。重新导入 Excel 时，仅替换上一次由 Excel 生成的记录；后续手工数据不会被导入流程删除。

数据库同级的 `backups` 目录保存自动安全快照。数据安全窗口可以另存完整 `.sqlite3` 备份、恢复备份或导出 `.xlsx` 数据包。恢复前会先校验备份并自动保存当前数据库。

## 成本与收益规则

- 每次买入都会生成一个独立持仓批次。
- 部分卖出按“到账金额 ÷ 卖出前总市值”计算卖出比例，再按 FIFO 从最早批次核销对应成本。
- 理财到期会结清该渠道下该产品的全部剩余批次。
- 市值由用户手工录入；更新市值不改变成本，旧值保留为历史快照。
- 高频市值维护集中在持仓页，可一次更新全部产品；“记一笔”不再展示市值更新入口。
- 阶段估值收益使用每次主动估值的“更新后市值 ÷ 更新前市值”，买入和卖出造成的市值机械变化不计为产品涨跌。
- 已实现收益等于实际到账金额减去本次核销成本。
- Excel 历史赎回优先采用 Sheet2 下半表的实际到账金额；同一产品、银行下的多个已结束批次先合并成本，再生成一条赎回流水。
- Sheet2 没有提供历史赎回金额时，程序才会按原成本生成“待核对”占位流水；可在流水详情中填写银行实际到账金额和日期。
- 分红直接计入已实现收益；费用作为负收益，不改变持仓成本和当前市值。
- 同币种账户转账只记录资金路径，不计入收益或总资产变化。
- 账户对账将银行显示的账户总资产，与本软件记录的该账户理财当前市值和有效定存本金比较；差额仅用于发现漏记或口径差异，不计入收益。
- 人民币账户差额不超过 1 元、美元账户差额不超过 0.01 元时视为已匹配；新的同日对账会覆盖该账户当天的旧快照。
- 撤销采用冲销方式：原交易永久保留，并新增一笔反向记录。为了保持批次连续，同一产品或存款需要从最新操作开始依次撤销。
- 修改手工流水同样遵循批次连续性：存在后续操作时从最新一笔开始修改；修改前自动备份，修改内容写入审计记录。
- XIRR 使用日期明确的投入和回款，并加入当前理财市值；缺少开户日期的历史导入定存不会强行参与计算。
- “待更新、积累数据、继续观察、关注加仓、考虑止盈、评估赎回”是规则化复核提示，不是收益保证；历史表现不能预测未来，操作前仍需核对期限、费用、流动性和个人风险承受能力。

## 数据表

- `accounts`：购买渠道和银行账户
- `products`：理财产品主数据
- `transactions`：买入、赎回、分红等交易流水
- `position_lots`：分批买入和持有状态
- `valuations`：按日期保存的产品市值
- `deposits`：定期存款合同
- `import_runs`：导入历史与校验警告
- `master_data_changes`：产品、账户和存款资料修改审计
- `account_balance_snapshots`：账户账面总资产和对账日期快照
- `historical_redemption_confirmations`：历史赎回的人工核对结果，重新导入时自动复用
- `excel_transaction_corrections`：Excel 买入流水的日期、金额和备注修正，重新导入时自动复用
